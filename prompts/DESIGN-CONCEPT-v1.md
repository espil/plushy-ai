# 디자인 컨셉 v1 - 전 에셋 단일 기준 (에셋 방)

기준일: 2026-11-08. 근거: Han님 지시 (에셋 제작은 한 가지 디자인 컨셉과 룰 아래에서 진행한다). 이 문서가 모든 에셋 제작의 단일 상위 기준입니다. 기존 규격 문서들 (에셋 일관성 규격, 파트 제작 규격, 무기 외형 규격, 스킬 아이콘 규격)은 이 문서의 하위 실행 규칙으로 그대로 유효하고, 충돌하면 이 문서가 이깁니다.

## 컨셉 (한 줄)

• 세계는 그림으로 읽히고, 모든 에셋은 하나의 팔레트와 하나의 비례와 하나의 음영으로 그려진 한 작가의 작업으로 보입니다.

## 1. 색 - 마스터 팔레트만 씁니다

• 앵커 색은 에셋 일관성 규격 v1의 실측 팔레트를 그대로 씁니다. 지면 잔디 #62B237, 식생 #BEC461 / #878F41 / #464F28, 흙 #956C34, 로그우드 #583D21, 석재 #716247 / #7E6F4E, 물 #61C7B8, 몬스터 가죽 #966F53, 외곽선 #2B2026, 등급 8색 #EBEEF0 / #FACD50 / #69DC82 / #50B4FF / #B482FF / #FF5A4B / #FFCD46 / #FF96CD
• 새 색은 만들지 않습니다. 앵커의 4단계 명도 파생 (×90/140/195/255)으로만 얻고, 채도는 앵커 ±15% 안입니다
• 순수 검정 #000000과 순수 흰색 #FFFFFF는 면과 외곽선 어디에도 쓰지 않습니다
• 납품 게이트: palette_check.py 적합률 92% 이상, 외곽선 색 위반 0

## 2. 비례 - 캐릭터는 2.5D 에버플래닛 베이스로 통일합니다

• 모든 2D 캐릭터 (플레이어, 주민, NPC, 손님, 원격 아바타)는 하나의 베이스를 공유합니다. 머리가 전체 높이의 약 1/3인 치비 비례, 머리가 어깨보다 넓고 팔과 다리가 짧게 압축된 형태입니다
• 캐릭터 간 차이는 비례가 아니라 텍스처와 파트로만 만듭니다. 주민은 사용자와 같은 베이스와 결을 쓰고 텍스처만 다르게 합니다
• 몬스터는 이 비례를 따르지 않습니다 (캐릭터 라인 한정 규칙). 몬스터는 종의 실루엣이 먼저 읽혀야 합니다

## 3. 음영과 결

• 음영은 4단계 명도로만 표현합니다. 부드러운 그라디언트 음영과 실사 질감은 금지합니다
• 겹치는 텍스처는 50% 그라디언트로 만납니다. 하드 엣지 접합은 금지합니다
• 외곽선은 전 에셋 #2B2026 하나의 따뜻한 검정으로 통일합니다

## 4. 픽셀 밀도 - 256 px/m 단일 기준

• 월드 스프라이트와 3D 텍스처는 256 px/m ±10%로 통일합니다. 벗어나면 재제작입니다
• 캐릭터 라인은 1024 캔버스, 인물 938px, Ground Zero (발바닥 y 1004, 중심 x 512) 규격을 유지하되 색은 위 팔레트를 공유합니다

## 5. 형식 - 2D와 3D의 경계

• 2D: 캐릭터, 무기, 스킬 이펙트, 풀밭
• 3D: 건물, 소품, 조경 (나무, 덤불, 바위)

## 6. 제작 방법 - 이것도 컨셉의 일부입니다

• 캐릭터는 베껴 쓰는 구조로 만듭니다. 민머리 무표정의 맨몸 베이스 위에 파트를 슬롯 순서대로 같은 좌표에 겹치는 방식 (MeowDB 빌더의 작동 원리)이며, 완성본을 굽는 방식과 기존 완성본을 편집해 나누는 방식은 제작이 아닙니다
• 베이스는 머리카락도 얼굴도 옷도 속옷도 없는 상태에서 시작합니다. 눈과 머리와 옷은 언제나 별도 파트입니다. 머리는 앞머리와 뒷머리로 나눕니다
• 캐릭터 파트와 몬스터는 샘플 1종을 먼저 완성해 Han님 판정을 받고, 통과한 뒤에만 확장합니다. 판정 전 전량 생산은 없습니다
• 색만 바꾼 파생 (틴트)은 최종본이 될 수 없습니다. 플레이스홀더로만 씁니다
• 납품 보고에는 수치를 붙입니다. 팔레트 적합률, 픽셀 밀도, 32px 실루엣 가독성, 그리고 세트 무게 (프레임당 평균 바이트와 세트 총 바이트)입니다
• 저용량도 완성도와 나란한 목표입니다 (Han님 선호, 2026-11-09: "왠만하면 저용량 2d 가 좋아"). 샘플 판정 기준에 무게가 들어갑니다. 4단계 음영의 평면 색은 WebP 품질을 낮춰도 화면에서 차이가 없어, 납품 인코딩은 무게 실측으로 정합니다 (기준 실측: q92 평균 약 79KB/프레임, q80 약 55KB로 전 크기 화면에서 차이 없이 약 31% 감소)

## 7. 생성 도구 (Plushy AI) 사용 원칙

• 생성 프롬프트는 PLUSHY-PROMPTS-v1.md의 고정 컨셉 블록을 항상 앞에 붙이고, 클래스별 템플릿으로만 제작합니다. 자유 프롬프트로 뽑은 그림은 이 컨셉 밖에 있어 제작으로 치지 않습니다
• 생성 결과는 원본이 아니라 재료입니다. 위 게이트 (팔레트, 밀도, 실루엣)를 통과한 것만 에셋이 됩니다
